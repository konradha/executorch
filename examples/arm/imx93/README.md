# ExecuTorch on i.MX93: A Hackable Fast Path

This directory is the Linux fast path for i.MX93 on the Cortex-A55 side.
It assumes the board already exposes a working `/dev/ethosu0` device.

Scope:
- export models for the i.MX93 Ethos-U65 Linux path
- build `executor_runner` against the NXP userspace driver stack
- inspect supported operators and model coverage
- benchmark under-documented Ethos-U55/U65 TFLite-style operators
- document official U55/U65 operator constraints alongside observed i.MX93 outcomes

Non-goals:
- remoteproc bringup
- M33 firmware loading
- debugfs tracing
- linker or resource table debugging

Apple Silicon workflow:
- use one micromamba env for export and another for the Linux aarch64 cross-build
- keep `rsmi` for export, quantization, and Vela
- create a dedicated cross env for the runner build:
  `micromamba create -n et-imx93-cross -c conda-forge python=3.10 cmake make ninja gcc_linux-aarch64 gxx_linux-aarch64 binutils_linux-aarch64 sysroot_linux-aarch64`
- activate the cross env in a fresh shell:
  `eval "$(micromamba shell hook -s bash)"`
  `micromamba activate et-imx93-cross`
- point host-side ExecuTorch codegen at the export env Python:
  `export PYTHON_EXECUTABLE="$(micromamba run -n rsmi python -c 'import sys; print(sys.executable)')"`
- point Python imports at this checkout before running any export command:
  `export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"`
- if you have the NXP userspace driver source locally, export `ETHOSU_IMX_DRIVER_SOURCE_DIR=/path/to/driver`
- if you want the helper to fetch a specific NXP driver revision, export `ETHOSU_IMX_DRIVER_GIT_REPO` and `ETHOSU_IMX_DRIVER_GIT_TAG`
- run `./examples/arm/imx93/build_linux_runner.sh --cross`
- if your checkout path is not named exactly `executorch`, the helper stages a temporary copy under `${TMPDIR:-/tmp}/executorch-fastpath-src/executorch`

Cross-build notes:
- do not reuse a general-purpose ML env for the runner build if it already exports host `CC` or `CXX`
- the helper expects `PYTHON_EXECUTABLE` to provide `torch`, `torchgen`, and `yaml`
- the cross helper uses `examples/arm/ethos-u-setup/aarch64-linux-conda-toolchain.cmake`
- if `CONDA_BUILD_SYSROOT` is present, it is used automatically; otherwise the helper falls back to `${CONDA_PREFIX}/aarch64-conda-linux-gnu/sysroot`

Practical hints:
- this tree defaults to `Dedicated_Sram` with `--arena-cache-size=98304`
- for 4D delegated tensors, keep the fastpath in `--channels_last_4d`; this is required for correct tensor storage ordering on the i.MX93 Linux driver path
- keep `PYTHONPATH` pointed at this checkout if you also have another editable ExecuTorch install nearby
- keep `_guards_fn` out of exported graphs
- do not use this flow to poke remoteproc internals
- `python -m examples.arm.imx93.operator_benchmarks --list` shows the operator microbench set
- the benchmark summary records Arm/Vela constraint hints plus compiler-estimated NPU operator counts and cycles
- `python -m examples.arm.imx93.supported_ops` prints the current U65 fastpath support matrix with official constraints and observed device status
- `python examples/arm/imx93/fastpath_delta_report.py > examples/arm/imx93/FASTPATH_DELTA.md` refreshes the detailed official-vs-actual delta report
- the delta report only covers the under-documented edge-op subset; it is not the whole delegated operator story
- the model-proven CNN core path is broader and includes convolution, residual add, relu/hardtanh, mean pooling, linear, view/layout helpers, and quant/dequant boundaries
- the current trusted delegated set is `cat`, `depthwise_conv2d`, `logistic`, `pad`, `resize_nearest_neighbor`, `slice`, `split`, `squeeze`, and `transpose`
- the open delta set is `argmax`, `prelu`, `reshape`, `resize_bilinear`, `strided_slice`, and `unpack`
- the authoritative constraint source for these notes is the Vela 4.5.0 supported-ops report generated by `micromamba run -n rsmi vela --supported-ops-report`
